03加密技术

消息发出去之前，就已经在你的手机上，用只有你和对方知道的密钥加密好了。

服务器收到的只是一串随机字符。没有那把密钥，谁也还原不出来 —— 包括开发者本人。

🔑
ECDH P-256
双方各持一对密钥，各自算出同一个共享密钥，私钥永远不出手机
🔒
AES-256-GCM
业界标准认证加密，带完整性校验，改一个字节就解不开
🧬
HKDF-SHA256
把共享密钥派生成独立的会话密钥，不同对话互不影响
📱
原生实现
加解密跑在 App 原生层，不依赖浏览器能力，环境再差也能用
基于 Signal 协议 · 业界公认最安全的加密方案
Signal 协议是目前全世界公认最安全的端到端加密协议。WhatsApp、Google Messages、Facebook Messenger 用的都是它，被全球密码学家审查了十多年，至今没有被攻破的记录。
悄悄借鉴了 Signal 的经典设计：先协商密钥，再用对称加密传消息。Signal 的完整实现还包含 Double Ratchet 双棘轮（每条消息换密钥，实现前向保密）。我们用的是简化版 —— 服务器解不开这一点完全相同，差别在于密钥被攻破时，历史消息的保护弱一些。
对比 Telegram 在某些关键点上，比它更彻底
Telegram 密聊走端到端，但服务器在 Telegram 手里。谁在什么时候跟谁聊了多久、消息体积多大、设备 IP —— 这些元数据他们全掌握。普通聊天更是明文存在他们服务器上。
悄悄 密聊走端到端，而且整个服务跑在你自己的机器上。不只是内容读不到 —— 连"谁在聊天"这件事，也只有你自己知道。
同样是端到端加密，区别是那台服务器归谁。

07常见问题
服务器真的看不到我的消息吗？
密聊里的消息，在你手机上就已经加密了。服务器存的是密文，没有密钥解不开 —— 包括开发者。

但普通聊天不是这样：那是服务器端加密，密钥在服务器上，为了支持搜索、备份、你在后台查记录。想要端到端，就开密聊。
换手机后密聊记录会丢吗？
会。密钥只存在当前这台手机上，不备份到服务器。

这是端到端加密的必然代价：服务器连密钥都没有，自然也没法帮你恢复。普通聊天的记录不受影响。
这算不算"最安全"的聊天软件？
准确的说法是：架构上做到了"服务器读不到"，用的是和 Signal 同一套思路。

但我们是简化版 —— 没有 Double Ratchet 双棘轮，所以密钥万一被攻破，历史消息的保护弱一些。Signal 完整版做得更彻底。
要花钱吗？有广告吗？
不花钱，没广告，不做推荐，不卖数据。

整套东西跑在自己的服务器上，成本是那台机器的租金。用户少的时候几乎零成本。
我的手机号会被用来做什么？
只在注册和第一次登录时用一次。注册完系统会给你分配一个数字 ID，之后手机号或 ID 都能登录，随你记哪个。

手机号不做通讯录匹配，不推荐"你可能认识的人"，不给第三方。

你还可以在「我 → 隐私」里对别人隐藏手机号，别人只能用数字 ID 找到你。
可以用 ID 登录吗？忘记 ID 会不会进不去？
手机号和 ID 都能登录，记哪个都行。登录时那一栏填手机号也行，填数字 ID 也行，密码不变。

注册后系统会分配一个纯数字 ID（比如 88888），在「我」页面能看到，也可以自己改一个好记的。

所以不用担心记不住 ID —— 手机号永远能进。ID 只是多给你一个选择，方便那些不想每次输手机号的人。
为什么有时发不出密聊消息？
最常见的原因：对方还没打开过新版 App，密钥还没生成，加密通道建不起来。

让 TA 打开一次 App 就行，密钥会自动生成并上传。另外在浏览器里（非 HTTPS）用密聊，加密能力不可用，也会被拦下。
数据存在哪？会被备份走吗？
存在你自己的服务器上，数据库文件和图片都在本地磁盘。

没有第三方云同步。备份要你自己做，也只有你能拿到。
08关于这个项目

这不是一个要跟微信抢用户的产品。

它只解决一个问题：当你说"这话只给你听"的时候，这句话在技术上真的成立。

主流聊天工具的加密，密钥握在平台手里。平台能看到、能分析、能被要求提供。我不想在这种前提下去聊私事，所以自己写了一个。

它跑在自己的服务器上，代码自己维护，没有第三方中转。加密用的是业界公开、被反复验证的算法，不是自己发明的。
