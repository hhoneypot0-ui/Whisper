# 悄悄 · Whisper

几个人的私密聊天。自建服务器，数据在自己手里。

> 没有广告，没有算法，没有第三个人在听。

**下载**：https://im.bierlan.ccwu.cc/download/

---

## 这是什么

一个**只给少数几个人用**的自托管聊天工具。整个项目由两部分组成：

| 部分 | 说明 |
| --- | --- |
| `server/` | Node.js 服务端，同时提供网页版和 API |
| `android/` | Android 外壳，把网页包成 App |

网页版本身就能用（加到主屏幕即可），Android 外壳只是补上浏览器拿不到的能力：麦克风、原生通知、文件选择器、返回键。

---

## 功能

### 加密与隐私

- **密聊** — 端到端加密，服务器只存密文，连管理员也读不到（v2.5 起）
- **阅后即焚** — 10 秒到 1 小时，到点自动消失
- **双向撤回** — 一键清空双方全部记录，不受 2 分钟限制
- **两步验证** — TOTP，密码泄露也不至于丢号
- **截屏保护** — 系统层面禁止截图
- **登录设备管理** — 每台设备的型号、系统、IP 一目了然，不认识的直接踢掉
- **隐身模式**、**已读开关**、**黑名单**

### 聊天

- **消息**：文字、图片、语音、文件、表情、贴纸、位置
- **群聊**：群主 / 群管理员 / 成员三级权限，自定义头衔（可设颜色）
- **频道**：公开频道可被搜索到，私密频道只能受邀，管理员单向下发
- **话题**：群里按主题拆成多个子频道
- **朋友圈**：发动态、配图、地点、点赞、评论、回复某人
- **消息操作**：撤回、编辑、引用、转发、置顶、搜索、按日期跳转、星标收藏
- **会话**：置顶、免打扰、特别关心、分组、删除
- **小玩意**：拍一拍、骰子、猜拳、投票、匿名提问、一起听歌

### 其他

- 赞助开发者、外观主题（玻璃 / iOS）、PWA、Web Push
- 中文 / English 界面切换

## 技术栈

```
服务端    Node.js 24 + node:sqlite（内置，无外部数据库）
通信      WebSocket（自研协议）+ HTTP REST
加密      消息与图片 AES-256-GCM 落盘加密
前端      单文件 HTML + 原生 JS，无框架、无构建步骤
外壳      Android WebView + JS Bridge
```

**零第三方运行时依赖**（除了 `ws` 和 `web-push`）。

## 加密是怎么做的

这里有**两套加密**，用途不同。

### 普通聊天：服务器端加密

消息用 AES-256-GCM 加密后写入 SQLite，图片加密后存磁盘、文件名是随机串。

**密钥在服务器上。** 所以管理员理论上能解密任何消息 —— 这是刻意的设计，为了支持多设备同步、全文搜索、备份恢复。

### 密聊：端到端加密

私聊可以「升级为密聊」。升级后：

| 环节 | 用的东西 |
| --- | --- |
| 密钥协商 | **ECDH P-256** —— 双方各持一对密钥，各自算出同一个共享密钥 |
| 对称加密 | **AES-256-GCM** —— 128 位认证标签，改一个字节就解不开 |
| 密钥派生 | **HKDF-SHA256** —— 从共享密钥派生出独立的会话密钥 |

```
你的手机                     服务器                    对方手机
   │                           │                          │
   ├─ 用会话密钥加密 ──────────►│                          │
   │  [变成乱码]                │   [还是乱码] ────────────►│
   │                           │                          ├─ 解密
   │                           │                          │  [看到原文]
   │                        ✗ 解不开
   │                        ✗ 看不到
```

**私钥永远不出设备。** 服务器被入侵、数据库被拖走，拿到的也只是一堆随机字符。

### 和 Signal 的关系

设计参考了 **Signal 协议**的经典方案 —— 先协商密钥，再用对称加密传消息。Signal 被 WhatsApp、Google Messages、Facebook Messenger 采用，是全球密码学界审查了十多年、至今没有被攻破记录的协议。

**差别在哪**：Signal 完整实现带 Double Ratchet 双棘轮（每条消息换密钥，实现前向保密）。本项目的密聊是简化版 —— **服务器读不到这一点完全相同**，差别在于密钥万一被攻破，历史消息的保护弱一些。

### 和 Telegram 的区别

Telegram 的密聊也是端到端的，但**服务器在 Telegram 手里**。谁在什么时候跟谁聊了多久、消息体积多大、设备 IP —— 这些元数据他们全掌握。

悄悄的整个服务跑在**你自己的机器**上。不只是内容读不到，连「谁在聊天」这件事也只有你自己知道。

**同样是端到端加密，区别是那台服务器归谁。**

### Android 为什么用 Java 原生做加密

Android WebView 里，用 `loadDataWithBaseURL` 加载的页面**没有 origin**，不是安全上下文，`crypto.subtle` 会被直接禁用 —— 而且失败时是静默的，界面上还显示"已加密"，实际发的是明文。

为了不让这种事发生，加密改在 Java 层实现（`E2eeNative.java`）。浏览器环境有真正的 origin（https 或 127.0.0.1），用 Web Crypto 即可。

另外，**环境不支持加密时，密聊消息会被拦下并提示，不会退化成明文发送**（v2.6 起）。

## 快速开始

### 服务端

```bash
cd server
npm install
```

准备密钥（第一次运行会生成，或手动写 `/etc/im-server/secrets.env`）：

```env
MSG_KEY=<32 字节随机 hex>
INVITE_CODE=<邀请码，留空则不校验>
VAPID_PUBLIC=<web push 公钥>
VAPID_PRIVATE=<web push 私钥>
```

启动：

```bash
node server.mjs
```

默认监听 `127.0.0.1:3001`，建议前面挂 Caddy 或 Nginx 做 HTTPS。

一键部署脚本见 `server/deploy.sh`（Ubuntu，含 systemd + Caddy + 每日备份）。

### Android

```bash
cd android
./gradlew assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

**改接口地址**：`app/src/main/java/.../MainActivity.java` 里的 `START_URL`。

## 架构要点

**为什么用 WebView 而不是原生重写？**

因为改一次网页，所有端立刻生效，不用重新打包发版。对几个人用的小工具来说，"改完就好"比"启动快 0.3 秒"重要得多。

代价是启动比原生慢零点几秒，用本地缓存 + 骨架屏把它压到了几乎无感。

## 隐私说明

- 普通聊天：AES-256-GCM 加密后写库，**服务器持有密钥**
- 密聊：端到端加密，**服务器不持有密钥，读不到内容**
- 图片加密后存磁盘，文件名是随机串
- 所有数据在你自己的服务器上，不经过任何第三方
- 不收集通讯录、不做用户画像、不投广告、不卖数据

**请明确**：普通聊天管理员能看，密聊管理员看不到。这个边界是清楚的，不是模糊的。
